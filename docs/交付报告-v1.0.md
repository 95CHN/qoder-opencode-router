## 2. 形态选型：为什么是 Skill 而不是 Plugin

读了 `plugin-creator/SKILL.md` 与 `create-skill/SKILL.md` 后，两者的边界很清楚：Plugin 是**面向角色的工具箱**（多 Skill + MCP 连接器编排），Skill 是**单一能力**。

| 判据 | 本任务实际 | 结论 |
|---|---|---|
| 能力数量 | 只有「派单—执行—验收」一条闭环 | 单一能力 → Skill |
| 是否角色套件 | 不是某职业的多任务集合 | 不需要 Plugin 的多 skill 结构 |
| 外部依赖类型 | 本地 CLI 可执行文件，**不是 MCP 服务** | `.mcp.json` / `CONNECTORS.md` 用不上 |
| 是否需要 hooks / agents | 不需要；环境自检按需跑 `doctor` | Plugin 的附加组件全是负担 |
| 分发 | 本地 ZIP 经 `install_extension` 安装，Skill 同样支持 | 分发不构成选 Plugin 的理由 |

套 Plugin 外壳只会多出 `plugin.json`、目录层级和维护面，用户调用时还多一层选择成本。**选 Skill**：`SKILL.md`（117 行）+ `scripts/router.py`（508 行）+ `references/`。将来若扩成「外包套件」（批量派单、成本统计、多工并发），再升级为 Plugin，把本 Skill 作为其中一个能力。

## 3. 连接方案论证：分体胜出，台账补齐可读性

### 3.1 成本对比

设系统前缀 S、单任务契约 P、单份报告 R。实测本机量级：S≈5k、P≈1.5k、R≈0.6k tokens。

| 指标 | 分体（每任务独立目录） | 合体（共用两份 md 追加） |
|---|---|---|
| opencode 单次输入 | S + P，**恒定** | S + Σ(P_i+R_i)，随历史线性增长 |
| n 个任务累计输入 | n·(S+P) | n·S + **O(n²)**·(P+R) |
| Qoder 读报告 | R，恒定小 | 全部历史报告，线性增长 |
| 串任务风险 | 目录隔离 + TASK_ID 校验，低 | 高：新旧指令同屏，免费模型易执行旧步骤 |
| 返工定位 | 同会话续跑，只发增量 | 长文里定位段落，易改错位置 |
| 用户可读性 | 差 → **用 INDEX.md 台账补偿** | 好 |

### 3.2 纠正一个关于缓存的误解

「合体追加会破坏缓存」并不准确：**追加在尾部时前缀不变，前缀缓存照样命中**。本机实测证据（opencode v2.3.0，deepseek-v4.1-flash-free）：

- 单步冒烟：`input=6437, cache.read=512`
- 两步任务的第二步：`input=152, cache.read=6912` ← 前缀几乎全命中

所以合体真正的代价不是缓存失效，而是：

1. **命中也要付钱**：cache read 仍是输入 token，历史越长每轮越贵，累计 O(n²)。
2. **上下文污染**：旧步骤、旧交付路径、旧验收标准与新任务混在一份文件里。免费模型的指令遵循能力有限，一次串任务的返工成本远高于省下的文件管理成本——本次实测就真实发生了（第 6 节）。
3. **Qoder 侧被动扩容**：读含全部历史的 report.md，等于把外包省下的词元又吐回去。

分体让每任务输入恒定，且 plan.md 派单后不可变 → 前缀稳定、命中可预期。

### 3.3 最终协议

```
opencode-tasks/
├── INDEX.md                     # 脚本维护，给人看；Qoder 默认不读
└── T20261119-151658-greet-cli-e2e/   # 目录名 = TASK_ID
    ├── meta.json                # 机器状态：ID/时间/模型/session_id/轮次/token/越界记录
    ├── plan.md                  # Qoder 写，派单后不可变
    ├── report-template.md       # 随任务下发，opencode 侧自包含
    ├── report.md                # opencode 写，Qoder 唯一读取的交工摘要
    ├── revision-01.md           # 返工增量
    └── run-*.jsonl / .err       # 原始日志，落盘不进 Qoder 上下文
```

用户溯源只看 `INDEX.md` 一页，要细节再点进任务目录。**可读性由台账解决，不牺牲执行隔离。**

## 4. 进度对齐机制（四重）

1. **TASK_ID**：`T<YYYYMMDD>-<HHMMSS>-<slug>`，目录名 = plan 头部 = report 头部，`verify` 字符串比对，串号直接 FAIL。
2. **时间戳**：plan 的 `CREATED_AT`、report 的 `REPORTED_AT`、meta 每轮 `at`，均带时区，可判先后、可识破旧报告冒充新交付。
3. **编号追溯**：plan 的 G（子目标）/ S（步骤）/ A（验收）↔ report 逐条自检 A1..An ↔ revision 的 P（问题）编号。验收靠对账，不靠感觉。
4. **ROUND**：首次为 1，返工递增；report 返工记录追加不覆盖，保留审计链。

## 5. 实现清单

| 文件 | 作用 |
|---|---|
| `SKILL.md` | 角色分工、词元纪律、五步工作流、模型选择、串号防护、安全边界 |
| `scripts/router.py` | 确定性工作全交脚本：`doctor / models / new / dispatch / revise / verify / index` |
| `references/plan-template.md` | 契约骨架（背景可选、G/S/A 编号、绝对交付路径、CHECK、禁止事项、完成信号） |
| `references/report-template.md` | 交工报告骨架，随任务下发 |
| `references/protocol.md` | 本文第 2–4 节的完整论证与失败模式表 |
| `references/troubleshooting.md` | CLI 缺失、代理、权限、串任务根因、超时、乱码 |
| `README.md` | 用户向快速上手 |

关键实现点：

- **CLI 探测**：`OPENCODE_CLI` → PATH → 桌面版自带 `resources/opencode-cli.exe`（含 update 目录）→ `~/.opencode/bin` → bun → npm → 常见 Unix 路径。本机只装桌面版也能直接用，缺失时给安装指引但**不擅自安装**。
- **模型解析**：接受模糊词（`deepseek flash low`）、完整 ID、只给变体（`low`）；变体白名单校验；默认 ID 失效时自动模糊匹配 deepseek+flash；匹配不到就列候选让用户选，不静默替换。
- **执行**：`run --auto --archived --format json --model ... --title TASK_ID`，cwd=任务目录，事件流落盘，只回显 ≤10 行摘要（EXIT/TOOLS/TOKENS/REPORT/LAST_TEXT）。
- **返工**：从事件流提取 `session_id` 存 meta，`revise` 用 `--session` 续跑原会话，复用缓存前缀，只发增量问题清单。
- **验收**：脚本做结构校验（TASK_ID 对齐、交付物存在且非空、可选 `CHECK:` 命令），Qoder 做语义验收（逐条对 A 编号）。
- **越界检测**：比对事件流里的 write/edit 路径与「任务目录 + 交付目录」，越界即 `OUT_OF_SCOPE` 判失败。
- **词元纪律**：禁止读 `opencode.db`/会话缓存/`run-*.jsonl` 全文；失败只 tail 末 20 行；台账默认不读。

### 6.2 事故：opencode 执行了上一个任务

首次 dispatch 时，opencode 没读任务目录的 plan.md，而是读了**项目根目录**那份冒烟测试留下的旧 `plan.md`，跑去桌面重写 `hello.py` / `report.md`，本次契约完全没执行（`REPORT: MISSING`）。

- **根因**：opencode 采信环境变量 `PWD` 决定工作目录。从 Git Bash 调 Python 脚本时，子进程虽设了 `cwd=任务目录`，继承的 `PWD` 仍指向 bash 所在的项目根。直接命令行调用时 `cd` 会同步更新 `PWD`，所以冒烟测试没暴露这个问题。
- **修复**：① 子进程 `env["PWD"] = 任务目录`；② 派单/返工提示词改用 **plan.md 绝对路径**，不再依赖「当前目录」；③ 新增越界写入检测。
- **验证**：重派后正确执行本次契约；用事故日志回测越界检测，准确报出 `Desktop\hello.py`、`Desktop\report.md` 两条越界写入。
- **副作用处理**：桌面上的旧 `report.md` 被那次误执行覆盖，我已恢复为冒烟测试时的原始内容；`hello.py` 内容前后一致（`print("Hello, World!")`），未受影响。

这次事故恰好证明了用户担心的「串任务」是真实风险，也证明分体目录 + TASK_ID 校验 + 越界检测这三道闸有必要。

## 9. 已知限制

- 单任务串行，未做多工并发派发。
- `CHECK:` 只支持「可执行文件 + 参数」形式，不支持 shell 管道与 PowerShell 专用语法（避免注入面）。
- 免费模型列表随 opencode 版本变化；默认 ID 失效时脚本会模糊匹配，仍失败需显式指定。
- 交付路径含空格时，plan 里请用引号包裹（脚本已支持引号路径解析）。
- 工作区目录受 Qoder 文件监视器影响，目录整体改名/删除可能报 busy；脚本只增不覆盖，不受影响。
- 台账的模型列显示该任务用过的档位链，token 明细在 `meta.json` 里。
